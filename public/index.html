      How to use Jig

      Jig builds Claude Code skills and agents from templates. This page says how to use it, what to pick when, and why each template is built the way it is.

      Quick start

      1. In the top bar, open Skills or Agents. Not sure which? Read "Skill or agent?" below.
      2. Pick a template. Each card says what it is for. The box under the cards lists examples of what it is good for.
      3. Give it a name and a description. The file on the right changes as you type. You can also edit the file by hand.
      4. Optional: choose who can start it, the model and the tools. Add references and scripts.
      5. Open the Checks tab. Fix every error. Warnings are advice.
      6. Save it into your project, or download a zip and unzip it in your project.
      7. Use it. A skill: type /name in Claude Code, or ask for the task and Claude loads it when the description fits. An agent: ask "Use the name agent to ...", or open /agents to see it.

      Skill or agent?

      SkillAgent
      What it isA procedure Claude follows.A separate worker with its own instructions.
      Where it runsIn your chat. Its work stays in your context.In its own context. Only a short result comes back.
      ToolsYours, with some pre-approved or blocked.Only the tools you list. This is a hard limit.
      ModelYour session's model, unless you set one.Its own model. A cheap one is fine for simple work.
      Use it whenYou want a method done the same way each time.The work is large or noisy, or it must not be able to change anything.

      Why not always an agent? An agent starts with an empty context and returns only a summary. For a small task that is slower than a skill.

      Why not always a skill? A skill's work fills your chat. A search or a long test run can use a lot of it. Give that work to an agent.

      They work together. An agent can follow a skill: add the skill under "Skills it follows". The agent then uses the skill as its steps.

      Which template?

      Skill templates

      TemplateUse it whenWhy it is built this way
      workflowYou do the same task in the same order again and again.Every step has a check, because a step with no check looks the same as a step that failed. It stops after two failed tries, so it never loops.
      investigateYou ask where something is, how it works, or why it fails.Every claim needs a file and a line, so you can check the answer yourself. It runs in its own context, so the search does not fill your chat.
      generateYou want a plan, a spec, a summary or a message in the same format every time.It never guesses: a gap becomes an open question. A Check line tells you if the output is right. You start it, because you know when the discussion is finished.
      reviewYou want a second opinion before you merge.Findings are ranked and end in a verdict. The edit tools are blocked, so it can only report.
      knowledgeClaude makes the same mistake with a tool, a library or your code.Claude already knows the basics. Only your own traps change what it does, so every line must stop a real mistake. It starts empty on purpose.
      guardrailClaude says "done" without proof.Claude must run the proof and compare it with the claim. The table of excuses answers the excuses Claude really gives.

      Agent templates

      TemplateUse it whenWhy it is built this way
      explorerYou need the right files before you answer or plan.It only reads, and it runs on the small fast model, because searching is cheap work.
      plannerA change touches more than one file and you want to approve the approach first.It only reads and ends with a plan you can approve. Each step has a check.
      implementerA plan is approved and you want it built without watching every step.It writes the check first, stays inside the plan, and stops after two failures. It is the only template that edits.
      reviewerYou want a review that cannot change anything.It has no shell and no edit tools. You pass it the diff in your message.
      testerYou have acceptance criteria and want tests before the code.It writes only tests. Each test must fail first, because a test that never failed proves nothing.

      A common chain: explorer finds the code, planner writes a plan, you approve it, tester writes the failing tests, implementer builds it, reviewer checks it.

      Who can start a skill

      ModeYou type /nameClaude loads it aloneUse it for
      You or ClaudeYesYesMost skills. This is the default.
      Only youYesNoWork with side effects: a release, a commit, a deploy. Claude must never start these by itself.
      Only ClaudeNo, it is hiddenYesBackground knowledge that is not useful as a command.

      Why it matters: Claude reads the description of every skill it may start, in every turn. A skill that only you start costs nothing until you call it. A skill that nobody can start is useless, and Jig reports it as an error.

      Tools: what really limits Claude

      These four settings look alike but do different things. I tested each one.

      SettingWhat it doesDoes it limit Claude?
      Skill: Allow without askingClaude can use these tools without a permission prompt.No. A skill with only Read, Grep and Glob allowed still wrote a file.
      Skill: Block these toolsClaude cannot use them while the skill runs.Yes, for those tools. A shell command can still write a file.
      Agent: ToolsThe agent can use only these.Yes. An agent with Read, Grep and Glob had no Write and no shell. This is the hard limit.
      Agent: a pattern such as Bash(git log *)It looks like a limit on Bash.No. The agent still ran ls -la. Use the plain name, and know that it allows every use.

      For a hard read-only guarantee, use an agent whose list has no Bash, Edit or Write. For a softer limit inside your chat, block the edit tools in a skill.

      Models and effort

      Model. "Not set" means Claude Code picks one. inherit uses your current session's model. You can also type a full model ID.

      A rule of thumb: use the small, fast model (haiku) for cheap work such as searching. Use sonnet for planning, building and review, where judgment matters. Use a larger model for hard problems.

      Effort is how hard the model thinks, from low to max. Higher costs more and takes longer. "Not set" is the normal level.

      Agent settings

      • Max turns. The most steps the agent takes before it stops. Always set it, so a stuck run cannot go on for ever.
      • Skills it follows. The agent follows these from the start. A skill that only you start cannot be loaded, so those are greyed out. The skill must exist in .claude/skills.
      • Permission mode. plan is read-only planning. acceptEdits accepts file edits. bypassPermissions skips every prompt, so use it only in a sandbox.
      • Memory. The agent keeps notes between sessions: user for all projects, project for this one, local for this one and not shared. Notes can go stale and nobody may read them. Use memory for an agent you work with every day. Leave it off for an agent that runs alone.
      • Work in a temporary copy of the repository. The agent works in a git worktree, so it cannot change your files while you keep working.
      • Always run in the background. The agent keeps running while you do other things.
      • MCP servers and removed tools. Give the agent the tools of an MCP server, or take a few tools away without listing all the others.

      References and scripts

      A reference is a file Claude reads only when it is needed. Use it for long material, such as an API guide or a style guide, so the skill itself stays short.

      The line "when to read it" decides if Claude ever opens the file. Name the exact moment: "when you write the release notes" works. "Details" does not.

      A file over 100 lines gets a table of contents, so Claude can jump to the part it needs. You can paste text, download a URL, or copy a file from your project.

      A script is code the skill runs. Claude runs it and does not read it, so it costs almost no context and gives the same result every time. Use a script when the output has a fixed shape.

      The checks

      Jig checks your file as you type. The result is in the Checks tab. The number on the tab shows how many problems there are, and its color shows how bad they are.

      BadgeMeaning
      0No problems found.
      2Advice only, for example a missing Gotchas section. You can still save.
      1Something is wrong, for example a bad name or a pointer to a file that does not exist. Save and Download are off until you fix it. Point at a button to see why.

      The check looks at the file. It cannot tell if the skill works well. After you save, run the skill on three real tasks and read what Claude did.

      Save or download

      When you run Jig on your machine (node scripts/ui.mjs), Save to project writes the files into .claude/skills or .claude/agents in the folder where you started it. The page never shows your folder path.

      When Jig runs as a web page, it cannot write to your disk. Use Download .zip. The zip has the right folders, so unzip it in the root of your project.

      Command line

      Everything the page does is also a command. Claude can run these for you.

      node scripts/skill.mjs templates
node scripts/skill.mjs new release-notes --template workflow
node scripts/skill.mjs new-agent plan-builder --template implementer --skill workflow
node scripts/skill.mjs add-reference .claude/skills/release-notes notes.md --when "you write the notes"
node scripts/skill.mjs check .claude/skills/release-notes

      The README has a block for your CLAUDE.md. After you add it, you can ask Claude: "Create a skill that writes release notes from the git log."

      Common questions

      Claude never uses my skill.

      The description must say when to use it. Claude reads only the name and the description to decide. Write what it makes and when to use it, in the words a user would say. Do not list the steps.

      Why can't my agent follow this skill?

      Only you start that skill, so an agent cannot load it. Change "Who can start it" to "You or Claude", or give the agent the steps another way.

      Why do I see a warning about allowed-tools?

      Your skill says it does not edit, but allowed-tools only skips the permission prompt. It does not block anything. Block the edit tools instead, or use an agent.

      I edited the file by hand and changed an option. Nothing happened.

      Jig does not overwrite your hand edits. Press Reset to rebuild the file from the form.

      Can I move or resize the panels?

      Yes. Drag the divider between the form and the file. Drag the handle at the bottom of the file panel to change its height. Swap sides puts the file on the other side. Your layout is remembered.
